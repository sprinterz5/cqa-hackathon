# Решения и почему мы их приняли

Каждое решение: что выбрали, из чего выбирали, почему, на чём основано (запись в `experiments.md` или факт), что может заставить пересмотреть. Отменённые решения не удаляем, помечаем «пересмотрено» со ссылкой на новое.

## R1. Аудио: таймкоды фраз берём из общей модели Alem, а не из казахской — 2026-11-07
Выбор: `speech-to-text` с параметром `language` для всех языков, включая KZ.
Альтернатива: `speech-to-text-kk` для казахских записей.
Почему: у казахской модели на `verbose_json` пустые `segments`, текст без пунктуации, на 52 с выпала целая фраза (E17). Без таймкодов не работает перемотка записи к реплике и доказательства по звонку.
Пересмотреть, если: запись режется на куски по паузам заранее (так сделано в ветке `islam`, E23) — тогда казахская модель получает короткий кусок, а время берётся из нарезки.

## R2. Роли говорящих: определяет LLM по смыслу, одним запросом на звонок — 2026-11-07
Выбор: gpt-oss получает все фразы с номерами и возвращает роль каждой.
Альтернативы: эвристика по ключевым фразам («меня зовут», «не могу»); разделение по голосу (SpeechBrain ECAPA, ветка `islam`).
Почему: Alem не различает говорящих; эвристика по фразам на DEV даёт 47 % (E17 ветки `islam`); разделение по голосу требует ~6 ГБ локальных моделей, которых нет на ноутбуке для демо. LLM уже подключена и бесплатна.
Пересмотреть, если: разделение по голосу доступно — тогда LLM определяет роль группы голоса целиком (см. R5).

## R3. Ответ модели о ролях — с номером фразы, а не просто список — 2026-11-07
Выбор: `{"roles": [{"n": 1, "role": "operator"}, ...]}`; до 10 % пропусков заполняются ролью предыдущей фразы.
Почему: на звонках p4-ru-001 и p4-ru-004 модель дважды вернула 79 ролей на 78 фраз; строгая проверка длины отбросила ответ, сработала эвристика, полторы минуты склеились в одну реплику, итог упал 71 → 15. С номерами лишний или пропущенный элемент ничего не сдвигает.

## R4. Отсекаем галлюцинации Whisper — 2026-11-07
Выбор: выбрасываем фразы с `compression_ratio > 2,4`, с `no_speech_prob > 0,6` при `avg_logprob < −1`, и повтор предыдущей фразы слово в слово.
Почему: на p4-ru-004 под музыку ожидания распознано «Я не могу ничего сказать» × 20; это стандартные пороги самого Whisper.
Риск: настоящий повтор («Алло? Алло?») тоже будет выброшен — для оценки по чек-листу это не критично.

## R5. Гибрид аудио-цепочек (план) — 2026-11-07
Выбор: одна точка загрузки, режимы выбираются по тому, что установлено:
1. разделение по голосу из ветки `islam`, если есть его библиотеки и модели;
2. роль каждой группы голоса целиком определяет LLM (видит всё, что сказал голос);
3. без локальных моделей — облачный режим: Alem STT + роли LLM по фразам (R2, R3).
Почему: сравнение на одной метрике — см. таблицу в `experiments.md` (E24). Облачный режим нужен для демо на любом ноутбуке; локальный — для пункта «разнообразие архитектур» и приватности.

## R6. Код критерия в results.json задаётся в редакторе чек-листа — 2026-11-07
Выбор: у каждого критерия выбор из 8 кодов организаторов; индикатор «все 8 кодов назначены».
Почему: организаторы допускают новый критерий на контроле и переоценку по нему. Раньше новый критерий не получал кода, и из `results.json` пропадал, например, `empathy` — файл не по формату ровно в контрольный час.
Код не входит в ключ кэша: смена кода не вызывает переоценку.

## R7. Отдельный фильтр «Грубые ошибки» с объяснением в списке — 2026-11-07
Почему: жюри прямо сказало, что на демо попросит «показать все диалоги с грубыми ошибками и объяснить почему». Раньше они были смешаны в «требуют внимания» с низкой уверенностью и апелляциями.

## R8. Облачная цепочка остаётся режимом по умолчанию для загрузки записи — 2026-11-07
Выбор: Alem STT + роли LLM — по умолчанию; локальная цепочка `islam` — дополнительный режим, если установлены её модели.
Почему (E24): на одной метрике 62,2 % правильных реплик против 47,1 % (локальная с эвристикой) и 60,1 % (локальная с обученным классификатором); быстрее в 3–4 раза; не требует ~6 ГБ моделей, поэтому работает на любом ноутбуке и у жюри.
Пересмотреть, если: гибрид «группы голосов ECAPA + роль группы через LLM» (задача Ислама) даст заметно больше 62 % — тогда он становится режимом по умолчанию там, где модели установлены.
